实际问题包含产品缺陷与过时 fixture，不能一概归入旧失败基线：

1. `WakeWorker.fail` 在事务内读取 Run 后没有锁定它，删除可在读取与最终更新之间提交；晚到失败会将删除取消覆写为 interrupted。完成路径已有 `outcomego_run FOR NO KEY UPDATE`，失败路径补齐相同锁序。改动仅为 fail 事务开始的一行，已和恢复线确认不重叠。
2. `ExternalDraftService.mutate` 和 `settle` 没有参与 Agent 生命周期锁。删除可能漏掉新产生的 `draft.response`，退休后的确定发送结果也可能因 enqueueWake 失败而回滚；归档 Channel 后仍可能产生新 Run。
3. 两处实际锁等待探测仍搜索 `%Run%`，但 Prisma 映射的物理表为 `outcomego_run`，导致真实等待未被识别。只修正查询，不降低等待断言。
4. settlement-first fixture 使用 cancel，却等待 enqueueWake。生产明确规定 discard 不唤醒，既有 `external-draft.integration.test.ts` 的 discarded outcome 检查也要求无新 wake。该屏障改为实际确定发送后的 settlement，保留“退休必须等到 wake 进入取消快照”的全部断言；retirement-first 的 discard 拒绝测试及普通 discard/no-wake 回归继续保留。
5. 草稿 fixture 的历史部分 manifest 不符合当前 SDK。采用 Ops 提供的正式模板/解析器 helper `c4fe41e6f7d77f85d18ad66a1d71bbaee5feaa79`，不是手工增加字段绕过校验。本地依赖副本为 `fe14a68de`，集成使用 Ops 原始提交即可。
