## 3. 六类故障 JSON 与数据库对账

```bash
for scenario in restart-running-run duplicate-finish-event interrupted-thread-resume concurrent-decision receipt-retry unknown-external-receipt; do
  bun scripts/test-outcome-recovery.ts --scenario "$scenario" --output "data/outcome-w3-evidence/$scenario.json" || break
done
```

输出使用 `wx`，已有文件不能覆盖；复跑须换目录/文件名。每个报告在清理 fixture 之前写出实际 initialState/finalState、注入 ID、replayed、outputCount、decisionCount、ID 和逐项 check。中途异常只可报告 FAIL/INCOMPLETE 和实际可查事实，不能伪造成功数量。需要自动测试形式时可以选择 `bun test ./scripts/outcome-recovery/scenarios.integration.test.ts`；这是同一组场景的另一入口，不要求无变化时重复执行两遍。

| 场景 | 实际注入/观察 | 必需数据库结论 |
|---|---|---|
| restart-running-run | 子进程提交 running+过期租约后 SIGKILL；观察精确进程退出；新进程调用恢复 | 未确认停止时不抢占；确认后旧 Run interrupted、仅一次新 continuation；foreground lease 完整 |
| duplicate-finish-event | 同一真实 completed Event/Run 重复结算，真实 Inbox consumer 重复处理，Review 同 key 并发 | 一个最终 Output、一个 Review 通知 intent/消费回执、一个 Review/Accepted 事件；无人工事实 |
| interrupted-thread-resume | 两次恢复后再次中断；每次重放 | 同 WorkItem/origin；最多两次自动恢复；随后一个 external_result_unknown Decision |
| concurrent-decision | 两个不同 key/选项并发 resolve，再重放胜出请求 | 一个成功、一个冲突；一个 continuation；批准快照不变 |
| receipt-retry | 真正 AssetStore 已上传；事务内 receipt.create 注入失败 | Evidence/Receipt/状态/事件/响应回滚；同 key 重试一个回执；提交仍等待；统一 Review 后一次续跑 |
| unknown-external-receipt | 虚构持久外部适配器接收一次后丢回执，注入 unknown 分类 | 不重新排入外部执行；needs_review/一个 owner Decision；不能推断真实 provider 已验证 |

restart 的停止证明只属于脚本拥有的本地 executor，不是远端 Computer turnCancel 证据。unknown 的适配器位于 test fixture，不是新增生产回执服务；生产 provider 发送与未知结果分类链仍须真实环境另验。

```bash

pg_dump --format=custom --file=data/outcome-w3-evidence/populated-outcome.dump "$OUTCOMEGO_TEST_DATABASE_URL"
```
