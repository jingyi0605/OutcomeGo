## 真实原因与实现

`Worker.fail` 已持有 Run 行锁，再通过 `reconcileRoutineExecution → routines.afterExecution → startEventFollowUp` 请求 Routine owner 的生命周期锁；真实 `BotService.archive` 先持有该生命周期锁，再停止同一 Run，形成反序。这个缺陷不同于已关闭任务 49 的普通消息发布与 Stop 规则。Routine 正常完成路径也会创建后续执行，必须保持同一顺序。

`lockRoutineRunLifecycle` 重新读取权威 Run 的 `origin/botId`；Routine 失败在原 Run 行锁前、正常完成在 Inbox/执行终结修改前获取 owner 生命周期锁。恢复路径使用同一权威查询，替换 task-58 中已有的 owner gate。普通消息终结路径没有新增生命周期锁；49/52 的 Run 行锁、显式 Stop 优先级，50 的记忆写入与恢复，以及 55 的退休持久清理均保留。不引入表、状态、接口或重试层。
