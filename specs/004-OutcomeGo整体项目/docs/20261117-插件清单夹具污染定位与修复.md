## 真实格式与兼容性

- `packages/plugin-sdk/src/types.ts` 的 `PluginDefinition` 仅声明可选 `schemaVersion: 1`。
- `parsePluginDefinition` 支持版本省略或 `1`，明确拒绝 `2`；连接、技能、
  `components` 数组均为必需。当前源码没有插件清单 v2 转换器。
- SDK 模板和生产安装、自定义 MCP 写入路径均包含 `components`。
- `external-draft-lifecycle.integration.test.ts` 原第 19 行只写
  `key/name/skills/connections`，缺少 `components`、版本和其他必需元数据；
  这不是受支持的旧版本完整清单。
- 设置查询读取全部安装记录，因而其他测试留下的残缺清单也会导致有效 OAuth 安装无法展示。

新增 `createReviewedEmailPlugin` 复用 `packaged-mcp` 模板并调用正式解析器，
保留 `email` 连接、`stdio`、`auth: none`、`send_reviewed_email` 和模板运行时文件。
生产清单读取、OAuth 交换、交接、幂等、取消和混沌测试断言均未修改。
没有增加可选链掩盖清单错误，也没有放宽解析器。

`task-52` 的文件负责人负责在生命周期夹具导入此 helper 并替换原清单，
避免并发编辑该文件。此提交交付 helper 和独立回归；最终组合验收必须包含该接入提交。
