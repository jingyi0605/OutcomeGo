# Spec 004.9 - Outcome 规划角色与任务分配

状态：Draft（只做规划，不开始实现）

## 一句话

目标管理里所有"规划"都由一个专门的规划角色（一个配置了高级模型的 bot）完成：写契约、拆分任务、指定每个任务由哪个 bot 执行。普通 bot 只做四件事：提交目标、被分配任务后执行、更新任务进度、提交验收证据。可选的审查角色先检查每个任务的结果：只有严重错误和遗漏才驳回，每个任务最多驳回一次，让原 bot 按意见修改；成果交付后再做一次整体初验，用户只对初验结果做决策。程序仍然只负责权限、幂等、状态派生和调度；批准契约与最终验收永远由用户完成。

## 为什么要做

- 现状：批准契约后只生成一个任务（`apps/server/src/services/outcome-service.ts:291`），交给契约里的 `executionBotId`。没有"把目标拆成多个任务并分给不同 bot"这一步，`OutcomeWorkItem` 上已有的 `dependsOn`、`botId` 字段没有被规划使用。
- 现状：规划线程绑定目标的执行 bot（004.8 `OutcomeThread.botId`）。规划质量取决于执行 bot 的模型，无法让"强模型规划、其他模型干活"。
- 现状：验收预审是后台一次性 LLM（`outcome-review-service.ts:264`），用户面对的是逐条验收项和原始产出，信息量大。

## 已确认的决定（来自用户）

1. 所有规划操作通过特定角色（高级模型）完成；bot 只提交目标、领取任务、更新任务、提交验收证据。不整体重构为"一个 bot 管所有目标"，bot 仍然只写自己负责的事实。
2. 任务采用**指定分配**：规划角色为每个任务指定执行 bot，不做任务池抢单。
3. 可选设置**审查角色**做初步验收，减少用户面对的信息量，用户只对初验结果做决策。最终验收仍由用户确认。
4. 规划角色与审查角色的回合并发上限各为 5，按角色分别计数，不占用执行任务每个 bot 并发 2 的名额。
5. 审查角色可以驳回普通 bot 的任务结果，让原 bot 按审查意见修改，每个任务最多驳回一次；非必要不驳回，优化项不驳回，只驳回严重错误和遗漏。因为每个任务都要审查，必须约束审查 bot 不能过度审查：驳回的依据只能是该任务覆盖的必需验收项或契约里真实存在的边界，并要写明理由；审查备注永远不会发给普通 bot；整体初验也只能把必需验收项标为不通过。
6. 初验标出不通过项时，界面不单独提供"交给规划角色重新规划"的入口（用户需要时发消息或返工即可，详见 `design.md` §8.2）。
7. 目标管理不止于代码编写，还有资料整理、文档编写、运维任务、现实任务、项目管理等。不能把代码管理的逻辑硬套到所有类型上：规划角色为每个任务声明性质（成果类或操作类）；只有成果类任务才做任务级审查和自动返工，操作类任务重做可能重复产生影响，所以不自动返工；现实任务沿用 004.4 的动作卡与人工回执，不由机器人审查；关于外部世界的事实只认外部记录、确定性检查和人工回执，不认执行 bot 的自述；规划与审查不产生任何动作授权。
8. 规划角色与审查角色应共享主 bot 的资料、记忆，但使用独立模型。推荐配置是：以主 bot 的身份运行规划与审查回合（沿用它的 persona、个人记忆、共享记忆、技能、文件），只把这些回合的模型换成单独设置的高级模型。核实发现现在所有运行共用一个全局模型，`Bot.inferenceModel` 不参与选择，所以"另建 bot"换不了模型；本 Spec 新增"按回合覆盖模型"（见 `design.md` §1.3、§2.4、§3.2.1）。
9. 开放为每一个 bot 单独设置模型的能力：每个 bot 可以有自己的模型（提供方、模型、推理强度），不再所有 bot 共用一个全局模型。核实发现 `Bot.inferenceProvider` / `Bot.inferenceModel` 两列已存在但没有任何代码读写，需要启用它们（并补推理强度）、开放更新接口、在 worker 选模型处接入。生效模型的优先级：子 agent 沿用父运行 > 角色回合的独立模型（决定 8）> bot 自己的模型 > 全局模型。只有用户能设置，bot 不能改任何 bot 的模型。这样执行任务也能按 bot 的擅长分配模型（例如写代码、写前端、联网检索的 bot 各用各的），规划角色看到的可指派 bot 清单显示每个 bot 的生效模型。
10. 第二轮复核后的取舍（详见 `design.md` §8.3）：
    - 任务失败后的目标状态：重规划回合排队或运行时保持 `running`；没有推进中的任务、存在失败任务且没有重规划在跑时显示 `failed`，不再让"一个任务失败、其余完成"的目标进入"待验收"。
    - 初验失败后不提供重试入口；审查驳回的发现用单一"理由"字段，保留依据校验、每任务一次、备注不外发；提交 bot 的背景说明字段后置。
    - 删除"非提交 bot 不能读其他目标"的限制（现状 `GetOutcome`、`ListOutcomes` 不按 bot 过滤，本 Spec 不新增可见性限制）。
    - 规划与审查回合的并发上限"5"是新增上限（线程回合现在没有按 bot 的并发上限），不是从 2 提高。
11. 先做规划，不写代码。
