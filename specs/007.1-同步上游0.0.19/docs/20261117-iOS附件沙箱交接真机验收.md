# iOS PDF 附件沙箱交接与清理验收

上游 `9fa7ca010` 的实际文件变更在 desktop/server/contracts，不在 iOS。Mac Pictures 下的 staging 已于 Phase 4 接入，本组不重复修改桌面代码，也不在 iPhone 创建 Mac 路径。按同一“系统交接返回后消费者仍可能读取文件”的生命周期，适配本地 iOS 的 Shortcuts/CoreTransferable 导出。

- `SystemIntentClient.exportAttachment` 改用 `Application Support/OutcomeGo/Transfers/<server-user-scope>/<UUID>/<filename>`，不受系统临时目录清理影响。文件 0600、目录私有，沿用持久附件的 completeUntilFirstUserAuthentication 保护并排除备份；重复文件名各自隔离。下载/账号校验失败清理未交接副本，成功交接后不按时间删除。
- 账号清理只捕获调用时、指定 scope 已存在的导出目录；异步 Spotlight 清理结束后才创建的新导出和另一账号导出不会被旧清理删除。遗留 OutcomeGoTransfers 临时副本按捕获列表兼容清理。
- Share Extension 现有 `loadFileRepresentation` 在 provider 回调返回前，仍先复制到私有文件，再结束 security scope；该正确顺序保留，失败不删除原始来源文件。本阶段不增加 iOS 直接发送 iMessage 的旁路。
- 生产路径使用现有 OutcomeGo 标识；没有导入安装器、签名、发布元数据或 upstream 目录。新增 SystemTransferFilesTests 源码验证权限、重名隔离、清理快照与跨账号边界，未执行。

静态验证：本组修改文件通过 swift-format 的 SwiftSyntax parser；不是沙箱权限/类型检查结果。

## 必须真机验收的 checklist

- [ ] 通过 Shortcuts 或系统附件导出取得 PDF，返回原 App 后再在 Messages/Files 中消费文件；预期字节完整、文件可打开，不因原 provider 的临时 URL/security scope 结束而失效。
- [ ] 导出两个同名不同内容的 PDF，关闭/重启 OutcomeGo 后再消费已有授权导出；预期互不覆盖。测试锁屏/解锁及首次解锁后的文件保护行为，确认符合当前系统交接权限。
- [ ] 从另一 App 分享 PDF 至 OutcomeGo，原 App 退出或撤销 provider 临时文件后完成上传；预期使用副本，成功清理副本，失败保留供用户处理，原文件不受影响。
- [ ] A 的导出清理在 Spotlight 队列中等待期间，重新连接同账号或 B 并导出新 PDF；预期旧清理不删新导出、不影响 B，A 账号退出时按要求清除旧授权文件。
- [ ] 通过 Bot 的 Mac iMessage 工具发送该 PDF，在 Mac 阶段确认沙箱交接后异步读取、部分失败/不确定结果及重启回执；预期不自动重复发送。该端到端步骤还依赖 Phase 4 的 Mac 和测试收件人。

回滚：revert 本组；旧导出代码恢复使用临时目录，已有 Application Support 导出不会自动被旧版本删除。先核实未完成系统交接，保留不确定文件；确认消费完成后再人工清理。新目录不设自动年龄回收，需评估长期磁盘占用。
