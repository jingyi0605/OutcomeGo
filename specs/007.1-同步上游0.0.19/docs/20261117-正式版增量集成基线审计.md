### 8.1 阶段 2 数据库部署与回滚前提（尚未执行）

当前 `@outcomego/db db:deploy` → `db:push` → `scripts/deploy-schema.ts`，并非 `prisma migrate deploy`。入口识别 `OutcomeGo schema ready/initializing: outcomego-v1:<fingerprint>`，fingerprint 来自 Prisma schema 与 raw SQL；识别到同族旧 fingerprint 时重新执行初始化链路。该链路还含历史退役操作，不能把它整体假定为仅 additive。

阶段 2 必须同时交付映射后的 schema、可审查的 additive SQL 及回滚 SQL，并确认它们与真实 deploy 入口行为一致。历史 migration 目录存在不代表生产部署会自动执行这些 SQL。不得运行 `--accept-data-loss`，不得擅改部署协议。

复制库验收至少包含：

1. 在已授权、隔离的复制数据库中保存部署前 schema/marker、关键表行数和约束清单；使用单独复制库 URL，不接触生产；备份来源和授权另行确认。
2. 执行本地实际部署命令并核对 SQL：只允许预期的新表/约束变化，旧表和记录保持一致；验证 Prisma 读写、数据校验和 feature flag 关闭时的旧客户端行为。
3. 再部署一次验证幂等与 marker 就绪；测试 interrupted deployment 恢复。
4. 先停用定位 feature，再回滚应用与本次 additive 数据库对象；验证 marker 与回滚版本 fingerprint 一致，旧版部署不能意外删除其他表；对定位数据的保留/清除处理在 runbook 写清。
5. 从复制库备份恢复复核，再验证旧版启动和现有外部消息数据/事件通道。记录实际命令、退出码和 schema diff；未执行项不得标为通过。

本阶段未连接数据库，未执行 migration 或 rollback；上述为阶段 2 的必交验收，不是已获得的通过证据。
