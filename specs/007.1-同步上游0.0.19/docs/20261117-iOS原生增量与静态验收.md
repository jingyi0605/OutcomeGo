## 契约与权限边界

- Swift 的 `SendInput.location` 为可选 `LocationSubmission`；结构是 `{fix, sharingRevision}`。fix 使用 `latitude`、`longitude`、可选 `accuracyMeters`、ISO8601 `capturedAt`、`device: "phone"`。身份仅由固定 API 认证会话决定，不接受位置内的 userId。
- 位置只在发送前附加到临时 input，不进入持久 outbox。未开启时保持旧消息形状；无精度字段的粗略定位也兼容。`LocationSharingState` 读取现有 GET 响应；PUT 用 `expectedRevision`，DELETE 触发已有服务端 tombstone。没有数据库迁移。
- `OUTCOMEGO_LOCATION_ENABLED` 仍由服务端控制，只有值 `1` 开启，默认关闭/404。iOS 不新增另一个全局开关；服务不可用时隐藏设置入口，本地 server/user 同意默认 false。Info.plist 仅新增 `NSLocationWhenInUseUsageDescription`，不增加 Always、后台 location mode 或后台常驻录音能力。
- 前台 Settings 的明确操作才能申请首次系统定位权限；Shortcuts 只复用既有同意，Share Extension 不附带位置且不申请 GPS。保留现有 AppIntent `.requiresAuthentication`，没有放宽跨 App 身份要求。
- 位置等待最多 1.5 秒，五分钟内缓存优先；API 请求超时三秒。关闭共享、权限撤销和切换账号更新本地 generation；在途发送有 50ms watchdog。服务端 revision 在事务中封锁旧修订，客户端无法撤回已经被服务器接受的消息，仍须按 nonce 核实。
- 离线 opt-out 先停止本地准备并保存 clearPending，回前台/进入设置时重试原账号 DELETE；重新启用前先完成清除。退出账号也记录待清除。未重连原账号时无法保证远端旧位置已删除，验收必须包括该情形。
- `SessionRecord.ownershipID` 是可选本地字段。新建连接生成 UUID，旧 Keychain 数据保持可解码；显示名刷新保留 ID。账号/服务器/token 校验叠加本地 epoch，阻止 A→B→A 使用相同 token 复活旧请求。语音迟到结果及错误通过 API generation 隔离，Share Extension 在异步边界复查并丢弃旧账号上传/目标缓存。
- PDF 导出保存于 `Application Support/OutcomeGo/Transfers/<server-user-scope>/<UUID>/<filename>`；目录 0700，文件 0600，排除备份，使用 completeUntilFirstUserAuthentication。成功交接不按年龄删除；异步清理只删除调用时捕获的旧 scope 文件，新导出和其他账号不受旧清理影响。

## 风险与回滚

1. 源码 parser 不验证 Swift 6 并发隔离、SDK API、AppIntent extraction、系统权限或 extension sandbox。必须通过完整 Xcode 编译和真机 checklist 后才能声称可交付设备。
2. 后台时间有限；强制杀进程、系统不给额度和长转写不保证完成。不要把后台时间申请理解为常驻语音。
3. 位置授权涉及敏感数据，默认仍关闭。离线清除可能延迟；回滚位置组前应先显式关闭并在原账号验证服务端已清除。已被服务器接受的发送无法通过取消撤回。
4. PDF durable staging 不做年龄回收，长期使用可能增长；退出账号会清理捕获的旧文件，可能使未完成的系统交接失效。变更保护等级的实际锁屏/首次解锁体验需真机确认。
5. 保留的 `testStalledDocumentFallsBackToText` 对所有 rich-markdown（含屏幕外行）断言不存在；上游曾改为只检查屏幕内范围。本阶段没有导入该断言变更，新增全树测量语义与旧测试假设的兼容性待实际执行，不声称通过。
6. 独立回滚使用 `git revert <能力提交>`，六组补丁在最终树分别通过独立 index 逆应用。无需数据库回退；位置组可整体撤回 App/Core/ShareExtension；PDF 回滚后旧版本不会自动清理新 durable 目录，应先核实正在进行的系统交接。不得删除 outbox/附件或跨账号合并数据。
7. 面向 OutcomeGo 的 draft PR 是阶段堆叠；在前序 PR 未合并前审核本阶段可用 `git diff f2ed5fcfa..merge/v019-ios-native`。不直接推送 OutcomeGo、不 force-push、不自行合并。

Phase 6 的机器人头像/设计 token 保持未采用。只有 Jackson 明确确认后才开始该可选阶段；预计确认范围后需半天至一天重新核对来源、列影响面和拟定可回滚提交，正式实现/设备验收另计。
