# iOS 全屏地图与地点照片验收

来源 `ef9c7091f`：只导入 MapKit annotation 显式注入 AppStore 的修复，以及新增的三次打开全屏地图 UI 测试源码。沿用 OutcomeGo 的 `PresentationMessageView.swift`、现有 fullScreenCover/路由和服务器代理图片路径。

MapKit 在全屏尺寸变化时会单独创建 pin 的 hosting view；该 view 不再依赖消息行隐式传递 AppStore，地点照片能够取得正确的服务器上下文。没有改头像、地图品牌/署名布局或地图 SDK 配置。

静态验证：两个 Swift 文件经 CLT swift-format 的 SwiftSyntax parser 解析，退出 0；不表示 MapKit/SwiftUI 类型检查通过。
编译、`xcodebuild`、`swift test`、新增 `testFullScreenMapWithPlacePhotosStaysOpen`：**not executed, reason: missing full Xcode**。

## 必须真机验收的 checklist

- [ ] 在测试服务器生成至少三个带照片的地点及连线/路线，进入地图卡，连续三次展开全屏、选中第二个 pin、关闭详情、关闭地图；预期无缺失 Observable AppStore 崩溃，当前会话与选中点保持正确。
- [ ] 分别用有效照片 URL、404、慢图、需要服务器认证的照片重试；预期有效图片经当前服务器加载，失败只影响图片，不崩溃、不把凭据传给其他域。
- [ ] 横竖屏、分屏/iPad 窗口、地图和地点详情之间来回，检查路线及 pin 可点击、不被 sheet/安全区遮挡；关闭全屏后原消息列表位置保持。
- [ ] 全屏打开期间切后台再恢复、切账号后返回原地图页面，检查旧会话的迟到照片不进入新账号；此项必须在真正沙箱/网络权限环境完成。

回滚：revert 本组的四行生产修复、新增 UI 测试和此 checklist，恢复原地图路由；无数据库、资源或契约迁移。回滚后原全屏带照片崩溃风险会恢复。
