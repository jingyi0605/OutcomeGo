# 2026-11-15 同步决策记录

## 结论

采用上游 0.0.19 的可靠性修复，并以 OutcomeGo 的运行身份、配置兼容性和现有产品行为为边界完成适配。已完成的补丁可以进入分批提交和代码审查阶段。

## 决策

| 决策 | 取舍 | 原因 |
| --- | --- | --- |
| `adopt` | Routine 编辑器恢复上游保存与恢复状态机 | 这是功能正确性问题；保留 OutcomeGo 的 i18n、Webhook 和现有 API 语义 |
| `adopt` | Messages 附件发送、partial 结果和 durable receipts | 这些能力直接影响消息是否重复发送或丢失，属于用户可见的可靠性契约 |
| `adopt` | Computer 用户信息和动态 catalog 快照 | 重启、summary 和模型前缀缓存必须共享同一 durable epoch |
| `adapt` | 网络 worker 接回 family health 和 host bridge watcher | 采用上游生命周期，但保持 OutcomeGo 的 DNS resolver、IPv6 抑制和 status 输出 |
| `adapt` | 网络策略脚本恢复 family/bridge handlers | 采用上游安全校验和原子更新，改用 OutcomeGo 的 nftables table、TUN、run 文件和镜像路径 |
| `preserve` | `/home/box/.config/openteam` 及 `openteam:` 协议标识 | 这些是现有用户数据和固定 IPC/fixture 协议，直接改名会造成兼容性回归 |
| `adopt` | Settings 的网络协议和麦克风 loading 接线 | 现有组件已经具备正确结构，补父组件挂载即可消除死代码 |
| `defer` | 远程 Debug Computer rebuild | 本轮只完成源码、镜像脚本和本地测试；根据项目规则，远程 rebuild 需要单独授权 |

## 风险复核

- 网络脚本恢复了对 `/home/box/.config/openteam/imessage-bridge.json` 的读取，但只接受 owner-only regular file、字节上限、明确 IP、HTTP(S) 和合法端口。
- host bridge 规则先撤销 nftables 标记，再移除旧 source-selection rule，避免撤销窗口继续走错误路径。
- Messages 附件发送在结果不确定时不自动重试，避免已经提交的附件重复发送。
- Routine 保存保留服务器 revision 和用户最新控制意图，避免晚到的响应恢复旧状态。

## 后续边界

本轮没有启动开发服务器、渲染脚本或远程 Computer，也没有创建提交。依赖安装产生的 `bun.lock` 变更应作为依赖同步单独审查。
