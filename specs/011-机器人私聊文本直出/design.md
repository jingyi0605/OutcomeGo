# 设计文档：机器人私聊文本直出

需求定义见 [requirements.md](requirements.md)，验证和状态见 [tasks.md](tasks.md)。

## 1. 模式与缓存

worker 按 `streamBotReplies`、运行身份及通道归属决定 `directTextReply`，同时将该决定用于平台提示和 computer 工具。开关沿用现有默认关闭值，自动化与成果上下文沿用独立作用域。语音指导仍可随对话消息变化。普通、语音、分支和外部来源回合共用系统提示与工具，按来源控制预览和交付适配。比较哈希时固定资料、工具配置与压缩纪元。

文本模式在原 `SendToUser` 位置挂载 `SendRichMessageToUser`，沿用完整富消息定义。暂缓动态加载，保证问题或审批无需额外发现往返。平台提示 v34 在文本模式分支改写开场、正文、问答及交付说明。模型可能输出较多过程文字，提示要求仅写有实质意义的内容，实机验证时关注冗长输出。

worker 根据当前交付模式选择开场及失败补救提示。构建提示时，把独立的已安装技能目录读取与代理文件核对并行执行，保留目录顺序与已有文件导入规则。

## 2. 增量、落库与顺序

首个 `text_delta` 触发现有发布器，发送累积正文与 `text:${assistantId}` 标识。客户端以现有的 `tool:${callId}` 关联预览和已保存回复。`agent.delta` 及 Pi 历史继续独立保存。

Pi 写入会话记录后派发 `message_end`。订阅安排内部 `SendToUser`，复用 `executeOutcomeGoTool` 与 `sendChain`。Pi 工具拦截和回合结算等待正文交付。普通结束且无工具时传 `end_turn: true`，含工具时传 `false`。现有通道 `(channelId, clientId)` 唯一键或外部调用回执负责去重。重投相同标识时，已保存的首个交付为准。

## 3. 语义映射

| 需求 | 旧语义 | 新语义 |
| --- | --- | --- |
| 1 | 工具结束回合、等待用户及同批暂缓 | 正常独立正文合成结束信号。显式富消息问题及同批暂缓沿用原规则。 |
| 2 | 多次工具发送走 `sendChain` | 正文进入同一发送链，先于同批富消息，沿用计数与确认。 |
| 3 | 正文工具或 tapback 确认 | 成功交付的正文计入确认。保留 tapback、未确认拦截和语音旁白例外。 |
| 4 | 无回复最多三次补发 | 文本模式要求直接写正文，沿用上限与交付计数。 |
| 5 | 工具分流至通道、外部转发、引用、卡片 | 富消息及合成调用进入同一服务端入口。外部与分支预览由代码控制。 |
| 6 | 工具参数增量切句并去重 | 正文累积增量以同一标识切句。在工具模式继续解析工具参数。 |
| 7 | 工具参数触发预览，按标识衔接消息 | 正文增量触发同一协议，撤回异常正文并允许重试。 |
| 8 | 内部投影和通道消息独立 | 两条管道保持各自职责，压缩读取混合的原生历史。 |

## 4. 失败与恢复

提交仅接受 `stop` 或 `toolUse`。用户停止、错误、截断以及已结束回合跳过未完成正文的保存。撤回等待同一标识的在途预览发布完成。正文落库可独立完成。交付以服务端成功回执为准，失败的正文不用于确认且撤回对应预览。外部回执不确定时停止自动补发，避免重复发送。已送达的语音无法撤回，停止待发片段。沿用输出长度提醒与重试方式。256K 后台压缩根据文本模式统一启用，预览开关不会改变同一模式的阈值。

## 5. 验证与上线

现有远程日志中，同模型 `auto/minimax-m3.1-flash` 的首个模型增量为 3258–8573 毫秒，观测到的预览发布调用耗时为 29–33 毫秒。旧样本缺少提示与工具哈希以及客户端可见时点。新增日志只输出指纹和计时。

本地使用 Pi 回环与模拟供应商分片检查交付和哈希。远端按校验和预检、授权、备份、同步、重建的顺序更新 debug computer 与 memory-init。容器健康，`scripts/dev/debug.sh check` 通过。worker 与 computer 需协调升级，可关闭开关恢复旧交付。

实机使用独立的 `Streaming QA` 私聊，同一模型五次用户回合均以正文直接回复。首个正文增量为 1782–2360 毫秒，首正文到服务端接受预览为 25–35 毫秒。五次请求的系统提示与工具哈希分别为 `b2350cf5`、`3da2d886`，读取缓存为 27996–28808 token，占各自已报告输入量的 99.0%–99.6%。旧样本的会话、上下文大小和缓存冷热不同，同负载命中率验收仍待复测。

三个桌面样本分别在发送后 4.30–4.63 秒读到完整首句。根据主机时钟偏移和辅助功能采样时点，首个正文增量到客户端观测的估计上界约为 251–295 毫秒。随后查询确认最后一个样本保存了一条对应 `clientId` 的通道消息。发送到发出供应商请求约 2.05–2.31 秒，已测队列等待为 116–293 毫秒。独立测量的提示组装耗时从单次 1.31 秒变为三次 0.83–1.15 秒。三秒首句目标、线上语音、实际外部转发、分支和移动设备端到端计时仍需验证。
