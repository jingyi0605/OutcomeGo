范围：[任务 6.4、6.5、6.7、6.9](../tasks.md)；对应[需求 B3、B8、B10、B12、D](../requirements.md)与[设计 §4.4、§4.5、§4.8、§4.12、§8.14 至 §8.17](../design.md)。

## 6.5 核对清单

- 代码、数据模型、待办提示词与四个工具描述未枚举场景；提示词测试扫描固定场景词。[示例](20261124-场景示例.md)中的两个例程示例只映射成测试里的两组不透明夹具。
- 来源引用只用于格式校验、去重或与已绑定规则的来源类型做等值收窄；标题、标签和概括不决定权限、状态、时限或展示分区。
- 两组不同来源类型、来源标签、标题、标签和概括经过同一条例程路径：默认进分诊、重复不新增、到期退出分诊、绑定规则时成为待办，无真实例程记录时保持建议。
- 所有者引用时限、待办建议过期天数、分诊上限、每日自动接受上限和紧急通知都读取 `TASK_POLICY_FIELDS` 对应策略；代码保留的数字是格式、规模或时间单位换算。
- 所有者消息引用由运行记录验证；例程、事件与唤醒不能伪造授权。待办交接只使用既有的给 bot 发消息路径；待办字段作为数据传递，不授权对外动作。
- 真实调试环境的例程演练未做。待所有者允许且复核会话完成远端构建，再用两组夹具中的一组走查分诊、重复与规则命中。

## 偏差与风险

- todo-bot-1：桌面和移动客户端共用既有所有者会话认证，无可信的桌面设备类型凭据。规则、交接及目标关联只接入桌面界面；服务端按所有者会话鉴权，不依赖可伪造的客户端标记。若要求服务端区分客户端，需引入可信设备认证。
- todo-bot-2：规则外键不约束历史待办；写入时快照规则名，停用、改名或删除规则不改变已接受待办。`db push` 不部署迁移的检查约束，规则写入及匹配同时在服务层要求可信绑定。既有空库整链错误 `P3018` / `42P01` 不属本次迁移；新增迁移用事务隔离 schema 验证升级及旧数据不变。
- todo-bot-3：待办升级沿用现有目标创建接口，另用所有者待办关联接口完成收尾。如果目标已创建但关联失败，同一表单保留目标 ID 以便重试，不重复创建；两步间未实现跨页面恢复。
- todo-bot-4：交接进展从关联请求读时推导，不写新待办状态；已打开的仪表盘沿用既有请求进展刷新。自动接受的桌面设置和分诊入口由 D 负责。
