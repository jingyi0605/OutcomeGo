# 任务全景视图远端与所有者验证清单

适用范围为 [任务清单](../tasks.md) 的阶段 0、阶段 1 至 3 检查点，以及活动与通知的真实环境验收。会话 A 未执行下列远端步骤。复核者先记录服务端、worker、computer、桌面端和移动端的版本，确认使用专用测试账号、目标和接收设备。真实对话、远端同步重建及调试库只读访问分别以所有者授权为准。证据保留脱敏的运行标识、时间、状态及截图，避免记录对话原文、凭证或推送令牌。

| 验证条件 | 对应事项 |
| --- | --- |
| 本机可做 | 1.3、1.4、2.7、2.9、3.1、3.2、4.3、4.4 的界面和键盘走查；2.5、2.7、2.8、2.10、4.3 至 4.5 的相关自动化用例。证据记在对应任务。 |
| 远端 computer 或真实 bot | 0.1、0.3 的续跑及缓存，1.3、1.5 的真实规划目标，2.5、2.8、2.10 的真实排期与延后，4.3、4.4 的实际请求进展。 |
| 所有者操作或授权 | 为 0.2 指定只读调试库、为 2.7、2.9、3.2、3.3 提供已连接的测试桌面、为 4.5 提供真机。D4-5 由所有者决定。 |

## 阶段 0

| 任务 | 操作与证据 | 通过条件 |
| --- | --- | --- |
| 0.1 请求续跑与来源 | 用测试对话触发 `Task`，让父请求通过 `ReportRequestProgress` 保存将来的 `checkAt`，结束本轮。保持 worker 正常，不额外配置例程，记录到期前后的 `requestProgress`、`requestNextCheckAt`、请求修订和检查日志。另以例程 `WakeParent` 唤醒父 bot，在该轮再派发 `Task`。对照直接的 `routine` 和 `outcome` 来源。 | 到期前没有核对回合。到期后以 `background_revival` 与 `request.check` 触发一次，关联同一个请求，状态从 `waiting` 转回 `working`。重复扫描不再产生同一修订的核对。例程唤醒后的父回合按实测归类，直接来源按独立来源边界核对。记录是否具备放宽必须建例程的依据，供 0.4 与设计 §10.2 第 19 项复核。 |
| 0.2 遵从度 | 在所有者指定的调试库用只读模式查询固定时间窗的 `Run`，从可确认 `Task` 派发的运行确定去重的根请求集合。以请求修订或可关联的工具调用记录统计有后续进展更新的请求，并分开汇报启动、后续更新、无法归类的数量。记录样本窗口、来源、过滤条件、分子和分母。 | 可以重算出后续更新比例。若工具或修订历史缺失，单列缺失样本并标明限制。依比例与样本质量判断活动区默认内容是否足够，记录补强建议。 |
| 0.3 提示词和缓存 | 按[阶段 0 基线](20261124-阶段0核实与基线记录.md) §3 重渲染同一组变体。用真实测试对话采集一轮 `inference.metrics`，记录同一提供商和模型下归一化的 `cachedInputTokens` 与总输入 token。 | 长度表可与 27,328、22,473、27,545、25,797 等基线逐项比较。缓存占比使用含缓存的总输入为分母，报告原始计数与比例。缺指标时写明提供商及日志缺项。 |

## 目标排期和桌面验收

| 任务 | 操作与证据 | 通过条件 |
| --- | --- | --- |
| 1.3、1.5 | 以真实规划目标生成多个有依赖的任务，等一项任务产生实际段，在桌面目标详情点击「更多详情」打开时间线。对照详情接口的任务和分段。 | 任务顺序、实际段、开始结束、依赖和未排期提示匹配同一目标。记录旧数据降级与语言、主题的回归结果。 |
| 2.5、2.10 | 在同步过工具契约的真实目标执行回合，安排一个可安全延后且有后续依赖的测试任务。等待该轮调用 `DeferWorkItem`，记录到期前后任务、工作意图、运行 ID 和 `outcome.schedule.changed`。重复同样流程观察上限拒绝。 | 调用后本轮结束，任务为 `queued / deferred_by_agent`，下游未放行，原运行不被结算成任务完成。到点只续做一次，意图为 `resume_scheduled` 并保留说明。上限和无效输入的拒绝未修改状态。可用独立经授权的调试 worker 重启跨过到点，并以延迟恢复日志核对。 |
| 2.8、2.10 | 由真实规划角色执行两套测试目标，每套包含可以立即开始的任务与一个客观上只能较晚开始的任务。查看 `SavePlan` 结构和重规划结果，再批准一个计划并记录到点运行。 | 立即可做的任务普遍不填 `startAt`，受时间约束者才填。估时可省略，过去的已保存时间可在重规划保留，截止建议只在 `notes`，批准后到点一次放行。汇报实际样本及偏离，避免把提示词单测当成模型遵从度。 |
| 2.9 | 在真实桌面设置里为测试账号选择可用的规划与审查独立模型，重开设置后读回，检查导航及锚点。 | 两个模型分别保存，设置重开后值仍然正确，总开关关闭时键盘无法进入禁用分组。 |
| 2.7、3.2、3.3 | 用桌面 Electron 的 `datetime-local` 选择器，通过真实调试服务修改一条可编辑的人工任务日期与一个目标截止日。在另一个打开同一目标的桌面窗口观察 `goal.schedule.changed`。另尝试修改已开始的任务以及过期的 `action` 决策。 | 实际 `PUT` 只发变更字段并使用请求 ID。另一窗口读回生效日期和旗标，动作卡反映同一任务日期。已开始任务无入口或由竞态拒绝，错误显示在表单。错过排期决策在改到未来后撤回，契约哈希不变。记录原生选择器、焦点与窄窗口操作。 |
