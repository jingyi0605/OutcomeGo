## 集成接口

集成者负责 `app-service.ts` 和公共路由装配，Desktop 负责前台计时和诊断显示，本线不并发写这些文件。

服务构造为 `new OutcomeRecoveryService(prisma, messaging)`，以下方法返回现有 `serviceEffect`：

| 方法 | 路由与请求 | 响应 |
|---|---|---|
| `get(id)` | `GET /api/v0/outcomes/:id/recovery` | `OutcomeRecoveryPage` |
| `reconcile(id,input,actor)` | `POST /reconcile`，`{clientRequestId}` | 相同查询页；同键返回原响应，不强行成功 |
| `metrics(id)` | `GET /metrics` | `OutcomeMetrics` |
| `recordAttention(id,input,actor)` | `POST /attention`，`{clientRequestId,surface,seconds}` | `{recorded:true,seconds,surface}` |

请求合同位于 `@outcomego/contracts/outcome-runtime`。注意力 surface 为 `planning/decision/review`，seconds 接受大于 0 且不超过 300 的有限小数，表示一段前台时间增量；重试保留同一请求 ID。不要求客户端提供 revision 或主体，actor 由现有认证上下文生成。T 没有样本时为 null。

查询页为 `{outcomeId,items,notificationFailures}`。通知失败只返回 `{id,status,attempts,errorCode}`，错误码固定为 `notification_delivery_failed` 或 `notification_retry_exhausted`，不读取或返回 provider 错误正文。WorkItem 只返回 ID 引用、状态、原因、revision 和计数。

开关 `OUTCOMEGO_OUTCOMES_ENABLED=false` 或 `0` 停止新 Outcome 入队和 claim，容量等待继续保留既有 processing 意图并返回 `queued_for_capacity`，不会伪造 Run ID。集成者负责 server/worker Compose 环境透传和“只关闭新创建入口”的路由策略；查询、取消、对账、计时及已有 Decision/回执/验收事实仍可记录。
