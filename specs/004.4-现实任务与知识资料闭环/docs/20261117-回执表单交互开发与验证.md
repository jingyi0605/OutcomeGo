## 先红后绿的真实缺陷

初始 10 项交互测试结果：**7 PASS / 3 FAIL / 51 assertions**。三个失败均有真实挂载和可控异步顺序：

| 缺陷 | 修复前实际结果 | 最小修复 |
| --- | --- | --- |
| Receipt 成功返回后，父组件仍在刷新，原卡暂为 `in_progress` | 连续两次提交实际调用 receipt 两次，期望一次，收到两次 | 已确认提交进入 `submitted` 阶段并禁止新提交；权威卡状态或 revision 变化时释放本地确认状态并使旧请求失效，驳回并显式 resume 后可正常补交 |
| 网络恢复没有重新读取动作卡 | 初次读取后派发 `online`，读取次数仍为 1，期望 2 | 挂载时监听 `online`，只调用原有权威读取；保持当前未保存材料，不自动提交，卸载时移除监听 |
| 等待上传期间离开卡片，上传完成后仍继续写 Receipt | 实际 React root 卸载后释放上传 promise，receipt 写入次数为 1，期望 0 | 表单检查挂载生命周期；卸载后不启动 Receipt 写入，也不触发迟到的成功/错误回调 |

独立复核 task-74 又重现新增确认状态的时序回归：服务端已驳回，但旧成功响应迟到，会重新设置 `submitted`，使 resume 后仍无法补交。两种实际顺序（先 resume / 后 resume）均为 **0 PASS / 2 FAIL / 6 assertions**。最终以每次提交的 generation 对照权威卡状态/revision 和卸载生命周期，忽略过期请求的成功、错误和 finally；驳回时结束旧 intent，使显式补交即便内容相同也使用新 key。另实际执行第二次 Receipt 在途时第一条旧成功响应返回的场景，验证旧 finally 不会释放新请求的在途保护。

现有 workspace 已使用 `HumanAction key={route.id}` 隔离卡片，因此没有加入另一套跨卡片状态管理。异步读取继续使用已有 generation 检查，不用新缓存或重试平台。

修复不把 receipt 提交视为验收完成；成功后仍显示等待 acceptance review。已开始的上传或已发送的 Receipt 请求不声明被撤销；服务端已持久化但响应丢失时，通过重新读取状态与 receipt history 对账。

## 已执行的 18 项交互覆盖

| 测试 | 实际断言 |
| --- | --- |
| 网络错误后重试 | 输入摘要、字段、comment、外部记录和 observation 均保留；未改内容的第二次请求与第一次完全相同，包含相同 clientRequestId |
| 成功后的重复提交窗口 | 父组件尚未更新卡片时再派发 submit，不产生第二次 receipt 调用 |
| `online` 恢复权威状态 | 读取服务器的新 rejected 状态，保留当前未保存摘要，写入次数保持零 |
| 两个文件中第二个上传失败 | 第一个成功 ref 仍显示；首次不写 Receipt；重试只重传第二个文件，并提交两个成功 ref 与原 comment |
| 上传和 receipt 在途 | 真实 fieldset 禁用；重复 submit 事件不重复上传/写入；两个异步阶段正确显示状态 |
| revision 409 | 显示明确冲突，重新读取 revision 2，保留摘要、comment、成功 asset ref；不自动提交；显式重试只发新 revision、新 key，不重传成功资产 |
| 成功持久化但响应丢失 | 先显示网络错误；手动刷新读取 submitted 和 history；表单只读，强制再派发 submit 也不新增写入 |
| 驳回、resume、补交 | 刷新展示 reviewComment；rejected 时不能提交；显式 resume 后提交修正摘要、新 key，历史保留第 1 条并增加第 2 条 |
| 暂停和重新挂载 | 从真实输入保存摘要、步骤、已读 refs、原因；卸载并重新挂载后从服务器草稿恢复，paused 表单禁用 |
| 上传期间卸载 | 已开始的上传返回后不再写 Receipt |
| Receipt 在途卸载 | 已发送请求的迟到成功响应不通知已离开的卡片 |
| 重连读取乱序 | 最新读取返回 accepted 后，较旧 paused 响应不能覆盖，不能显示 resume |
| 不明确失败后重连再重试 | 重连只读取；成功 asset ref、comment、摘要及原 key 均保留，第二次提交不重复上传 |
| 422 缺材料及 404 资产不可用 | 展示各自错误，仍可编辑；显式修正后再提交，保留 comment 并产生与新内容对应的新 key |
| 409 后读取 cancelled | 保留输入和冲突提示，权威 cancelled 状态禁止后续 Receipt 写入 |
| 驳回后旧成功返回，再 resume | 权威 rejected 不被迟到成功重新锁住；可提交修正材料、新 key，展示第 2 条历史 |
| 先 resume，再收到旧成功 | 旧成功不能把已恢复的表单锁为 submitted，修正后的第 2 次提交正常 |
| 新 Receipt 在途时旧成功返回 | 即便材料相同，新补交 key 与旧请求不同；旧成功/finally 不释放当前在途保护，重复 submit 仍只发两次 |
