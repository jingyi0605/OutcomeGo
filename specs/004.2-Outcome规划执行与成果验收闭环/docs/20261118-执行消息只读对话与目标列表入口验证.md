# 执行消息只读对话与目标列表入口验证

日期：2026-11-18。对应需求 27 补充（执行消息只读对话）、设计 §41.2、阶段 16（任务 16.1–16.3 已完成，16.4 未执行）。改动在 `OutcomeGo` 分支主工作树，未提交。未启动服务、未发送 Bot 消息、未改变用户目标、未重建远端 Computer。

## 1. 背景与改动

原执行消息卡在目标对话卡片内展开，挤占卡片空间，且只有卡片和详情两处入口。本轮改为：

1. 卡片内只保留入口，打开参照 Bot 之间只读聊天的对话弹层（头像气泡、折叠的脱敏工具活动、“此聊天为只读 / 关闭聊天”）。图 2/3 的页面渲染的是 Bot 私聊消息，与 transcript 接口数据不同，因此新做独立弹层，只对齐样式与只读语义，没有复用其 ChatPane。
2. 全部目标列表行增加执行消息入口（草稿、规划中、待批准、待启动不显示），点击才读取该目标，不触发进入详情。
3. 对话目标卡片底部，入口与“查看目标”同行：“查看目标”保持原样式靠右，入口占满剩余横向空间。没有底部按钮行的阶段仍单独显示入口。

读取、`next_before` 分页、5 秒串行刷新（仅弹层打开且任务运行/排队时）、晚响应丢弃、失败重试、run 级 user 行过滤与不展示隐藏推理的语义沿用，未新增任何服务端接口。
