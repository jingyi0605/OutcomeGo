## 1. 来源浮层

原 `OutcomeSourceInfo` 将资料直接显示为纯文本，且 Popover Portal 默认在 body 下。目标 Dialog 的 RemoveScroll 只允许自身内容区域滚动，位于 body 的非模态 Popover 因而可能被滚轮锁拦截。

本轮复用既有 MessageResponse / Streamdown 进行 Markdown 显示。来源 Portal 放入最近的 Dialog 内容中，并以该 Dialog 为 collisionBoundary，避免浮层被容器边缘裁切。没有 Dialog 时沿用 body 容器。资料在有界区域内部滚动，减少滚动穿透；原悬停预览、点击固定和 Escape 关闭行为保留。上方方案 Info 以 Markdown 分段和列表呈现当前保存方案。

实际 Electron 通过鼠标滚轮将来源从背景/环境事实滚至后半段清理步骤和红线，背景目标与整个模态的位置未移动。`source-before-scroll.png` / `source-after-scroll.png` 保留该实际变化，期间未执行页面中的任务操作。挂载测试核对资料确实位于目标 Dialog 内，以及 Markdown 强调、段落与列表结构。

## 2. 已证实的刷新闪烁与边界

- Bot 头像 URL 带通用 `updatedAt` 版本。版本变化时原资源 hook 未启用既有同身份保留能力，旧图会先被清空；Radix Image 在重新解码时也可能切到 fallback。本轮使用现有按 Bot ID / 凭据代际隔离的资源保留，并保持同一原生 img 节点显示旧图直到新图可用；网络或解码失败仍能退回既有机器人头像，身份切换不能显示上一个 Bot 的照片。
- 实际挂载复现：初始图片成功显示，再在第二次图片请求尚未完成时变更相同 Bot 的版本。旧实现预期的 img 节点变为 null：`avatar-red.log` 为 0 PASS / 1 FAIL，3 assertions；修复后相同图片节点和旧 src 在请求期间保持，替换完成仍是同一个节点，改为其他 Bot 时立即清空旧图。前期缺少 Linkedom 解码元数据的失败保存在 `avatar-harness.log`，不作为产品缺陷证据。
- Outcome 对话卡片原来把同一目标的每次 `updatedAt` / 重试读取都当作身份切换，先清空 current 和 actions，再装回，导致内容闪现和展开项丢失。本轮只在 Outcome 身份改变时清空；同目标后台读取保留已显示事实、展开内容和真实事项，失败仍明确表示最后保存状态。挂载测试使用受控延迟验证同一个概览 DOM 节点和展开项在刷新前后均保留。

**整窗闪烁边界**：用户报告的“整个窗口每 2–3 秒闪一次”没有被本轮独立、持续复现。实际检查时该目标已在等待人工处理。本轮修复了上述已证实刷新缺陷，未据此断言 GPU、Electron、开发热更新或所有整窗闪烁原因均已排除，也没有通过暂停真实任务来制造验证场景。

## 3. 只读执行消息卡

现有 transcript GET 已能按 Outcome / agent WorkItem 读取持久化观察记录，原入口只在执行诊断中以 JSON 显示。本轮新增共享 OutcomeExecutionCard，用在目标对话卡片与详情；不添加服务端写入接口。

- 默认只显示“执行消息 · 只读”，展开才读取；优先选当前版本正在运行的 agent WorkItem，也可切换本版本其他有 Run 的任务。
- 最新记录优先展示。Bot 回复使用既有 Markdown；工具活动单独折叠，按需查看服务端已脱敏投影。run 级 user 行包含执行和调度输入，不作为 Bot 回复显示；不读取隐藏推理或私有运行时磁带。
- 使用既有 `next_before` 与 GET 查询显示较早记录，提供回到最新记录和手动刷新。分页有界，不一次挂载全部运行历史。
- 只有消息卡展开且保存任务状态为 running / queued、正在查看最新页时，才每 5 秒串行刷新；关闭后清理定时器。刷新期间保留旧消息，错误可重试；请求按 Outcome / WorkItem / 分页键匹配，旧任务的晚响应不能覆盖新任务。
- 没有消息输入、发送、接管、继续执行或审批按钮。不会把观察操作路由到前台对话，也不会改变 Run、Decision 或人工任务状态。保留原历史版本诊断读取入口。

实际在既有 Unraid 目标的对话卡片和详情中读取到已有 Bot 回复、工具活动及时间/状态，并确认工具输出默认折叠。当前目标等待登录人工操作，该检查未完成或代为执行登录。截图为 `execution-card.png`。
