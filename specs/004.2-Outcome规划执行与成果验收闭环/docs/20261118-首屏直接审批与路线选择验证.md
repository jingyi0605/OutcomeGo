## 1. 首屏就是当前动作

目标打开后，“现在需要你”直接显示可操作控件，背景、前提、风险与任务仍在其后独立展开。

| 类型 | 默认展示与操作 |
| --- | --- |
| 待批准方案 | 一句方案摘要、可选意见输入、“是，批准”和“否，修改”两个直接按钮；无默认选项、无稍后、无单独确认按钮 |
| 实际路线决策 | 最多四条服务端选项、各选项行尾 Info、允许自定义时独立的一行空白输入与一次提交 |
| 明确的成对是否决策 | 已保存的两项标签明确为 Yes/No、批准/拒绝等成对词时，直接显示对应按钮，意见在按钮上方 |

批准按钮继续调用原服务，以 `expectedRevision`、幂等请求 ID 和明确确认文字提交；填写的意见随确认文字保存。当前批准文字上限为 500 字符，因此界面意见限定 400 字符，预留明确确认前缀，不静默截断。

否定方案使用意见生成新的候选建议，原方案保持未批准、未执行。意见可为空，此时按“不同意当前方案，请给其他建议”生成；不强制额外填写。不把否定按钮解释为取消目标或替用户批准新版本；新的候选仍使用原 `baseRevision` 确认后保存。若用户未处理，则没有任何业务请求。

实际路线决策在详情页直接复用现有 `DecisionCard` / `DecisionController`，不再跳转到另一个页面才出现选项。原收件箱的直接 Decision 页面也使用同一布局。未凭两条任意路线或其 effect 猜测“是否”类型；非明确是否标签保留路线选择。每个选择最终效果来自保存的服务端快照。

## 2. 选项简洁，解释按需

首层仅显示服务端原选项 label，不拼接长后果或来源、不自行生成替代语义。Info 按钮和选择标签独立，打开资料不能勾选该路线。选项后果、推荐理由和来源通过既有 Markdown 渲染器展示，使用 `**会发生什么**`、`**为什么推荐**`、`**来源**` 分段加粗。支持原 reason 或匹配推荐项的 recommendation reason，不丢失原推荐信息。

自定义输入始终可见（原快照允许时），输入文字即选中独立自定义项，无需先展开或点选；输入后可直接提交，也支持表单回车。正文保留用户原始空白及意见，不用自定义内容修改原选项 effect。原 `customEntryAllowed=false` 的快照继续保持服务端限制，不从界面伪造可写选项。

详细完成记录、问题、证据、历史契约和执行来源放入后方的按需区域；首次打开才挂载该详细上下文并读取对应附加材料。来源 Info 继续支持 hover、点击固定、Escape 与外点关闭。Decision 和目标基础读取仍沿用原 API，不将首屏隐藏等同于服务器未返回完整数据。

## 3. 版本与重试保持

沿用原 Decision 状态机：提交中禁用、过期/撤回不可提交、409 重读权威版本后保留输入但不自动重试。明确是否按钮将实际 option ID 和允许的评论一并交给原 resolve；模糊网络失败保持相同请求 ID。自定义路线和“已选路线附意见”使用不同输入语义，不把先前自定义草稿误当另一条已选路线的附加授权。

内嵌 Decision 的完成回调只按实际结果通知一次，避免父组件刷新使回调反复执行。目标首屏的选择不会触发额外页面导航。待批准 successor 清除上一版的评论和候选内容；历史回执和资料版本仍按原路径读取。

提交中或已结束时只禁用意见、选项输入和提交按钮，不整体禁用包含资料图标的 fieldset，因此已记录决定的解释仍可查看，不能再次提交。
