# Spec 010 - 群任务看板

状态：In Progress

## 一句话

在群聊里为多个 bot 提供一块共享的任务看板：群里的任何工作都先由 bot 登记任务、认领任务，再动手；同一任务同一时刻只有一个负责人，其他 bot 看到后不再重复去做。

## 文档

- `requirements.md`：需求与验收标准
- `design.md`：设计、数据模型与接口契约
- `tasks.md`：任务拆解、验证方式与回写状态
- `docs/`：补充材料（当前为空）

## 参考

- DSH（deepseek-harness）智能体团队任务看板：任务是带单调 `revision` 的完整快照，所有变更使用 compare-and-set，任何成员可创建、可认领“就绪且无人认领”的任务，已删除任务保留墓碑。本 Spec 采纳其“单调版本 + 条件认领 + 不物理删除”的做法，并按 OutcomeGo 群聊的接力式轮次做了裁剪。

## 与相邻 Spec 的关系

- 004.7（Outcome 任务看板）：Outcome 是“用户的个人目标”，服务用户的待办与决策；本 Spec 是“群内 bot 之间的协作分工”，只在单个群内可见，不进入用户收件箱，也不要求用户批准或验收。两者数据与工具互相独立，互不替代。
- 002.1（群聊实时语音对话）：语音群聊同样是群频道，复用同一块看板，不单独处理。
- 005 / 计算机运行时：新增 bot 工具需要同步并重建远端 computer 容器后才在 bot 侧生效（见 `tasks.md` 阶段 4）。
