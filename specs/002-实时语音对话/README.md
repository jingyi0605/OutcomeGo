# 规格文档：实时语音对话

状态：草案

日期：2026 年 11 月 6 日。

分支：`spec/realtime-voice-conversation`。

本规格文档定义 macOS 桌面端、iOS 客户端和 Android 客户端之间双向实时语音对话功能的技术实施方案。OpenTeam 服务端负责管理经过认证的语音会话、音频解码、语音活动检测、流式语音识别、Agent 回合协调、流式语音合成、中断、配额和可观测性。第一阶段同时接入火山引擎豆包语音和 Deepgram，并通过 Provider 无关的适配器边界支持在配置界面选择当前使用的 Provider。

该功能采用服务端终止的处理链路：

```text
客户端麦克风（系统回声消除）
  -> Opus 音频帧
  -> 经过认证的语音 WebSocket
  -> 服务端解码和 VAD
  -> 流式语音识别
  -> 现有 channel/run/worker Agent 执行
  -> Agent 通过 SendToUser 发送的可见回复
  -> 语音文本规范化和流式语音合成
  -> Opus 音频帧
  -> 客户端播放
```

现有语音笔记流程继续支持。语音笔记是录制完成后上传进行批量转写，再将文本放入编辑器的功能。实时语音使用独立的会话协议，不改变语音笔记的行为。

文档包括：

- `requirements.md`：产品行为、范围、验收标准和非功能目标。
- `design.md`：架构、协议、状态机、持久化、Provider 边界、安全控制和完整文件影响清单。
- `tasks.md`：可执行实施任务、依赖关系、检查点和验证证据。
- `docs/development/specs/20261106-实时语音对话技术方案.md`：项目入口和决策记录。

在以下内容完成前，本规格文档保持草案状态：使用一个 macOS 客户端验证媒体编解码链路、流式 Provider 行为、`SendToUser` 驱动的首段音频延迟、中断延迟和外放回声消除。
