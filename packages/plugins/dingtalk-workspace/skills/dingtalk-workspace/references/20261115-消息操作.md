# 消息与应用提醒

先用根 Skill 的包装入口。需要的是当前 OAuth 用户可见的会话数据，不能把机器人只接收 @ 消息的限制外推到 DWS 个人消息命令。

## 定位和读取

先唯一定位会话或发送者，保留实际返回的 `openConversationId`、消息 ID、发送者 ID 和时间。

```bash
dws chat +unread-chats --format json
dws chat +recent-conversations --help
dws schema --cli-path "chat +chat-messages" --compact --format json
dws schema --cli-path "chat +search-msg" --compact --format json
```

普通消息使用有时间范围、页数或条数限制的 `+chat-messages`。搜索结果的 snippet 不一定是完整正文，需要时通过返回的消息 ID 读取；不要编造摘要之外的内容。应用消息/通知是否能读取由会话类型、当前账号权益和服务端接口决定：查不到时报告实际限制，不能把空结果当作账户没有提醒。

## 回复和发送

```bash
dws schema --cli-path "chat +messages-reply" --compact --format json
dws schema --cli-path "chat +messages-send" --compact --format json
```

用用户实际选定的原消息 ID 和会话 ID 构造引用回复；DWS 可区分当前用户、机器人和 Webhook 身份。默认保持当前用户身份，用户明确要求机器人时用机器人路径，不静默换身份。

发送前核对组织/账号、接收方、原消息和最终正文。取得针对这次发送的用户授权后，按契约的确认参数执行；保存 `openTaskId` 等结果，并通过发送状态查询确认实际成功，不能仅凭命令退出码声明已送达。结果未知时先查询，禁止自动重发。

工作通知、待办提醒或卡片未必支持文本回复；若没有可回复会话，说明不支持，在用户授权后用相应待办动作处理卡片引用的资源。不得为了测试发送给无关同事。

## 事件

```bash
dws event +listen-im --help
dws event schema user_im_message_receive_group --flatten --format json
dws event schema user_todo_task_update --flatten --format json
```

即时消息用 `+listen-im`；待办等非 IM 事件用 `consume`。在事件契约允许时指定群、发送者及有界时长。监听会创建订阅和维持长连接，需要用户任务确实要求实时接收；普通查询不要启动。只有用户明确要求全部消息才订阅全量事件；不要把后台监听加入系统开机任务。
