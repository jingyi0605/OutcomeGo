# 待办操作

先用根 Skill 的包装入口执行下列 DWS 命令。下列 shortcut 的 flags 与确认语义以固定二进制的 compact Schema 为准。

## 读取和定位

```bash
dws todo +get-related-tasks --format json
dws todo +get-my-tasks --format json
dws todo +due-today --format json
dws todo +overdue --format json
```

`+get-related-tasks` 覆盖当前用户作为创建者、执行者和参与者的待办并去重；执行列表与全部相关列表不是同一视图。分页游标或页码原样续传，保留 `taskId`、完成状态、截止时间和当前角色。`task list` 的企业 OpenAPI 与 DWS 个人待办接口不同，不要套用旧企业列表 API 的限制声称所有个人待办不可读，也不要未经完整分页声称覆盖客户端全部项目。

已知 `taskId` 时可读取详情：

```bash
dws todo task get --task-id <taskId> --format json
```

## 创建和处理

按当前版本叶子契约选择：

```bash
dws schema --cli-path "todo +remind" --compact --format json
dws schema --cli-path "todo +complete" --compact --format json
dws schema --cli-path "todo +update" --compact --format json
```

仅在目标和动作已经获用户授权后执行写入。标题相似或多个组织存在相同任务时先明确对象，不默认选择第一项。先查询当前状态，已完成且无需修改的任务不重复写。优先使用含读回验证的 `+complete` / `+update`；检查结果的验证状态和部分失败，必要时以同一 `taskId` 读回。

提醒时间和截止时间不同；缺少提醒所需字段时不要假装已经设置提醒。审批、智能填表等业务待办可能需调用源业务能力完成，修改提醒或回复通知不能代替源业务审批。

## 实时变化

用户要求监听时，以有界时长或明确后台生命周期运行 `event consume`，订阅 `user_todo_task_create`、`user_todo_task_update`、`user_todo_task_delete`；先查看对应事件 Schema 和角色过滤参数。事件只负责通知；处理动作仍走待办命令。不要为等事件写循环轮询列表。
