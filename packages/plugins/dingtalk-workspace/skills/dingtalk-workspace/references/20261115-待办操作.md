# 待办与审批操作

先用根 Skill 的包装入口执行下列 DWS 命令。下列参数和确认语义以固定二进制的 compact Schema 为准；涉及写入时，先执行 `--dry-run`，再在用户明确授权后执行实际命令。

## 我的未完成待办

默认列表是当前用户作为执行者（`executor`）的未完成待办：

```bash
dws todo +get-my-tasks --status false --all --max-pages 40 --size 20 --format json
```

分页约束：

- 必须带 `--all` 才会按页获取。
- `--max-pages` 只能与 `--all` 一起使用，范围为 1–40。
- `--size` 范围为 1–20。
- 是否已获取全部结果只看响应里的 `data.complete`。`true` 才能报告“全部”；`false` 必须说明结果不完整。

时间和输出约束：

- `dueTime` 是毫秒时间戳，也可能为 `null`。未完成且 `dueTime < 当前毫秒时间` 的项目标记为逾期。
- 每条待办都要输出 `taskId`、标题、内容简述、当前角色、截止时间和逾期状态。**内容简述是强制字段，不能只列 ID 和标题。**
- 列表结果没有足够正文时，逐条补查：

  ```bash
  dws todo task get --task-id <taskId> --format json
  ```

  以详情中的标题、正文、备注或业务摘要生成一两句简述，不臆测未返回的内容。

示例输出结构：

```text
1. taskId=<id> · <标题>
   内容：<一两句说明这项待办要处理什么>
   角色：executor · 截止：<时间或未设置> · 逾期：是/否
```

“我创建的待办”是单独视图：

```bash
dws todo +created-todos --format json
```

该入口不提供与 `+get-my-tasks` 相同的状态过滤，可能包含已完成项目。不要把它和执行者待办直接合并后声称都是未完成。

也可以按目标查看今天到期或已逾期项目，但这些快捷入口不能替代上面的完整分页命令：

```bash
dws todo +due-today --format json
dws todo +overdue --format json
```

## 识别审批待办

先读取待办详情。若 `bizTag` 为 `certify_todo`，且 `detailUrl` 同时包含 `procInstId` 和 `taskId`，该项目实质上是 OA 审批。记录其中的流程实例 ID，并进入 OA 流程。

不要执行下面的命令来处理审批：

```bash
dws todo +complete
```

它只处理待办记录，不会改变 OA 审批状态。

## OA 审批流程

### 1. 列出待处理审批

`oa +list-pending` 的两个时间参数都是必填项，并且单位是毫秒：

```bash
dws oa +list-pending --start <startMillis> --end <endMillis> --format json
```

如果缺少 `--start` 或 `--end`，命令会校验失败并以代码 3 退出。`oa +list-pending` 与 `oa approval list-pending` 是两个不同入口，前者的 flags 不能直接套到后者。

### 2. 读取实例详情并选择正确的任务

```bash
dws oa approval detail --instance-id <procInstId> --format json
```

必要时先获取当前登录用户：

```bash
dws contact user get-self --format json
```

从详情的 `result.tasks[]` 中选择 `userId` 等于当前登录用户的任务，并使用该项的 `taskId`。一个 `procInstId` 可能包含多个任务；不能按数组位置选择，也不能把 `procInstId` 当成 `taskId`。同时读取 `result.formValueVOS`，用于说明申请人、日期、事由和其他表单内容。

### 3. 预览并提交审批

先预览：

```bash
dws oa approval approve \
  --instance-id <procInstId> \
  --task-id <taskId> \
  --remark "同意" \
  --dry-run
```

用户明确授权当前实例和意见后，再实际提交：

```bash
dws oa approval approve \
  --instance-id <procInstId> \
  --task-id <taskId> \
  --remark "同意" \
  --yes
```

审批写入必须同时携带正确的 `procInstId` 和 `taskId`。如果用户只说“处理一下”但没有明确同意、拒绝或其他意见，先展示表单内容并询问。

### 4. 双路径验证

提交后使用与首次查询相同的时间范围重新执行：

```bash
dws oa +list-pending --start <startMillis> --end <endMillis> --format json
dws todo +get-my-tasks --status false --all --max-pages 40 --size 20 --format json
```

检查待处理审批数量是否减少，并确认对应的审批待办已经从未完成列表消失。审批通过后，钉钉通常会自动把对应待办标记为完成；只有两条查询都验证到，才能报告审批已经完成。

## 其他待办动作

已知 `taskId` 时读取详情：

```bash
dws todo task get --task-id <taskId> --format json
```

根据当前版本叶子契约选择提醒、完成或修改命令：

```bash
dws schema --cli-path "todo +remind" --compact --format json
dws schema --cli-path "todo +complete" --compact --format json
dws schema --cli-path "todo +update" --compact --format json
```

提醒时间和截止时间不同；缺少提醒所需字段时不要假装已经设置提醒。普通待办完成或修改前先核对 `taskId`、标题和内容简述；删除不可逆，执行前必须再次列出这些字段让用户确认。

## 实时变化

用户要求监听时，以有界时长或明确后台生命周期运行 `event consume`，订阅：

```bash
dws event consume user_todo_task_create user_todo_task_update user_todo_task_delete --flatten --format ndjson
```

先查看对应事件 Schema 和角色过滤参数。事件只负责通知，处理动作仍走待办或 OA 命令；普通查询不要启动监听，也不要为等事件写循环轮询列表。
