# 钉盘与授权文档

先使用根 Skill 的包装入口。用户给出链接时保留原始链接，通过当前 Schema 支持的读取命令查询真实节点和类型，不从任意 URL 片段猜测 ID。

## 搜索与读取

```bash
dws schema --cli-path "drive +search" --compact --format json
dws schema --cli-path "doc +fetch" --compact --format json
```

优先搜索用户给定的关键词或列举明确文件夹，按真实游标分页，避免下载整个云盘。普通上传文件、在线文字文档、电子表格和多维表格是不同类型，不能都按文本文档覆盖。

- 在线文字文档使用 `doc +fetch`。
- 普通 PDF/Word 等文件按 `drive +download` 的叶子契约下载，不把元信息当正文。
- 在线表格编辑使用 `sheet` 的精确范围命令，多维表格使用 `aitable` 命令；超出当前参考时先查实际叶子契约，不用 `doc update` 伪装编辑。
- 用户只有查看权限时只读；上传新副本不能冒充修改了原文件。

## 编辑与验证

```bash
dws schema --cli-path "doc +update" --compact --format json
```

先读取原文和目标块，再执行用户授权的最小修改。局部改动优先 block 更新，补充内容优先 append；整篇 Markdown overwrite 可能损失原生格式，仅在用户明确要求且已确认范围时使用。必要时使用当前契约的 JSONML、版本快照与 revision，版本冲突后重新读取，不能关闭检查强行覆盖。

多行或含 shell 特殊字符的内容写入临时 UTF-8 文件，通过叶子帮助支持的文件参数传入，避免命令插值破坏正文。写入后检查验证结果，部分成功、格式降级和待核对项如实说明；必要时重新读取目标块或文档，不把一次 `success=true` 当作完整验收。

下载、上传、重命名等文件操作与文档正文修改分开。权限变更、互联网公开分享、删除或覆盖本地文件均不是读取/编辑文档的默认附带动作。服务端权限错误应报告原原因，不尝试另一个账号或扩大分享范围绕过。

来源：官方 DWS `v1.0.68` 的 Drive 和文档参考；具体参数以固定二进制的 Schema 为准。
